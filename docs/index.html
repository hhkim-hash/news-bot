02레포 구조

파일은 4개뿐입니다. 위치가 틀리면 아무것도 동작하지 않습니다.

함정 · briefing.yml을 그냥 업로드하면 레포 맨 위(루트)에 올라가고 Actions가 인식하지 못합니다. 반드시 Add file → Create new file에서 파일명에 .github/workflows/briefing.yml을 통째로 입력하세요. /를 칠 때마다 폴더가 생깁니다.

03시크릿 등록

키를 안전하게 저장하는 곳. 한 번 넣으면 값은 다시 볼 수 없고 덮어쓰기만 됩니다.

  1. 레포 상단 탭 맨 오른쪽 Settings (한국어 화면은 설정)
  2. 왼쪽 Security and quality 아래 Secrets and variables → Actions
    바로가기: github.com/계정/레포/settings/secrets/actions
  3. New repository secret으로 아래 이름 그대로 하나씩 등록
NAVER_CLIENT_ID
NAVER_CLIENT_SECRET
SLACK_WEBHOOK_URL       # 채널 1 (#pr_research)
SLACK_WEBHOOK_URL_2     # 채널 2 (협업채널)
TYPESAFE_API_KEY        # AI 판단 (선택)
계정 설정과 헷갈리지 않기 · 프로필 사진 → Settings는 계정 설정입니다. 시크릿은 레포 Settings에 있습니다.

04워크플로 작성

"어떤 컴퓨터에서, 무엇을 설치하고, 무슨 명령을 실행할지"를 적는 파일입니다.

name: Boosters 뉴스 브리핑
on:
  schedule:
    - cron: '0 0 * * *'       # 매일 09:00 KST (UTC 00:00)
  workflow_dispatch:          # 수동 실행 버튼 + 외부 크론 호출용

jobs:
  briefing:
    runs-on: ubuntu-latest
    timeout-minutes: 30
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }
      - run: pip install -r requirements.txt
      - name: 뉴스 브리핑 실행
        env:
          NAVER_CLIENT_ID: ${{ secrets.NAVER_CLIENT_ID }}
          NAVER_CLIENT_SECRET: ${{ secrets.NAVER_CLIENT_SECRET }}
          SLACK_WEBHOOK_URL: ${{ secrets.SLACK_WEBHOOK_URL }}
          SLACK_WEBHOOK_URL_2: ${{ secrets.SLACK_WEBHOOK_URL_2 }}
          TYPESAFE_API_KEY: ${{ secrets.TYPESAFE_API_KEY }}
          PYTHONIOENCODING: utf-8
          PYTHONUTF8: 1        # 한글·특수문자 인코딩 오류 방지
        run: python boosters_news_briefing.py

커밋 후 Actions 탭 → Boosters 뉴스 브리핑 → Run workflow로 첫 테스트를 합니다.

05키워드 설계

마케터가 가장 자주 만지는 파일. 코드를 몰라도 여기만 고치면 수집 대상이 바뀝니다.

categories:
  global_eqqualberry:
    display: "🇺🇸 Eqqualberry 글로벌 PR"
    lang: en              # 미국 Google News(영어)만 검색
    always_show: true     # 0건이어도 "오늘 감지된 기사 없음" 표시
    max_articles: 10
    keywords: ["eqqualberry", "Eqqualberry skincare"]

  global_competitors:
    display: "🌐 글로벌 경쟁사 (영미권)"
    lang: en
    competitor: true      # AI 판단 대상
    keywords: ["medicube", "COSRX", "Beauty of Joseon", "\"d'Alba\" skincare", ...]

메인 키워드

우리 브랜드. 매일 "있다/없다"를 확인해야 하므로 always_show

경쟁사 키워드

브랜드명 15개. 흔한 단어와 겹치면 맥락어를 붙임

심층·트렌드 키워드

Ulta Beauty, PDRN skincare처럼 뷰티 맥락을 명시

실습 과제 · 자기 회사 브랜드 1개, 경쟁사 3개, 트렌드 키워드 2개로 카테고리를 만들어 보세요.

06노이즈 줄이기

"왜 이 기사가 왔지?"를 추적해 규칙으로 바꾸는 단계. 봇의 품질은 여기서 결정됩니다.

사례 A · 트러플 축제 기사가 경쟁사로 잡혔다

원인은 키워드 d'Alba. 검색엔진이 아포스트로피를 끊어 이탈리아 알바(Alba) 지역 기사를 가져왔습니다.

사례 B · 종목 추천 리스트가 경쟁사 기사로 왔다

"[리스트] MVP 상위 20선"류 기사. 기존 제외어(주가·주식)가 제목에 없어서 통과했습니다. 두 겹으로 막았습니다.

EXCLUDE_KEYWORDS += ["종목", "밸류에이션", "목표주가", "[리스트]", "상위 20선", ...]
EXCLUDE_DOMAINS  = ["itooza.com", "thinkpool.com", "paxnet.co.kr", ...]   # 종목 포털 통째로 차단
강의 포인트 · 엉뚱한 기사를 발견하면 링크만 AI에게 주세요. 어느 키워드가 끌어왔는지 재현해서 찾아줍니다. 사람이 추측할 필요가 없습니다.

07Slack 채널 연결

Webhook URL은 채널 하나당 하나입니다. 채널을 늘리려면 URL도 늘립니다.

  1. api.slack.com/apps → 봇 앱 → Incoming Webhooks → Add New Webhook to Workspace
  2. 채널 선택 → 허용 → URL 복사 → 03단계의 SLACK_WEBHOOK_URL_2에 저장
  3. keywords.yml의 channel2_categories로 채널 2에 보낼 카테고리만 고르기 (비우면 전체)
함정 · "본인의 팀이 소유한 채널을 선택하세요"
외부 회사가 만든 Slack Connect 채널에는 우리 쪽 웹훅을 붙일 수 없습니다. 해결: 우리 워크스페이스에서 새 채널을 만들고 외부 담당자를 초대합니다. 소유권이 우리에게 남아 웹훅이 바로 붙습니다. 초대할 때 "여러 결과 일치"가 뜨면 칩을 눌러 기존 외부 조직 사용자를 고르세요. 게스트 초대가 아닙니다.

08AI 판단 붙이기 (선택)

경쟁사 기사가 "우리에게 유리한지 불리한지"를 AI가 라벨로 붙이고, 칼럼·기획기사는 뺍니다.

기사 유형

단신 / 심층·기획·칼럼 / 광고성 / 기타 → 심층이면 제외

방향 (0~2)

이퀄베리 입장에서 불리·중립·유리. 경쟁사 호재 = 우리에겐 불리

영향 (0~2)

거의 없음 · 참고 · 즉시 검토

리스크

K-뷰티 평판 리스크 이슈 여부

설계 원칙 세 가지

  1. 경쟁사 여부는 AI가 아니라 설정으로 정합니다. competitor: true 카테고리만 AI를 부릅니다. 비용도 줄어듭니다.
  2. 확신도 0.6 미만은 "판단 보류". 유형이 불확실하면 빼지 않고 보냅니다. 놓치는 것보다 한 건 더 보는 게 낫습니다.
  3. AI가 실패해도 뉴스는 나갑니다. 키가 없으면 단계를 건너뛰고, 3번 연속 실패하면 호출을 멈추고 "❔ 판단 불가"로 표시합니다.
검증 · 지난 기사 30~50건을 사람이 먼저 라벨링하고 python jev_news_judge.py articles.json results.csv로 AI 결과와 비교합니다. 맞는 비율을 보고 켤지 결정합니다.

09스케줄 운영

"매일 9시"는 생각보다 까다롭습니다. 실제로 하루 두 번 오는 사건이 있었습니다.

사건 · 9시에 한 번, 11시 49분에 또 한 번

실행 시각표시정체조치
09:00Manually run외부 크론 서비스가 cron-job-boosters 토큰으로 정시 호출유지
11:30~11:49Scheduled워크플로 안의 cron: '0 0 * * *'. GitHub 자체 스케줄은 부하로 2~3시간 늦게 돔삭제

추적 경로: 레포 Settings → GitHub Apps 확인 → 프로필 → Settings → Developer settings → Personal access tokens에서 workflow 권한이 있고 "최근 사용"인 토큰 발견.

강의 포인트 · GitHub의 schedule은 정시를 보장하지 않습니다. 정시가 중요하면 외부 크론(cron-job.org 등) + workflow_dispatch 조합을 씁니다. 그리고 cron은 UTC 기준입니다. 0 0 * * * = 한국 오전 9시.

11정리 · AX 포인트

단순한 게 오래 간다

AI 요약·점수 단계가 오류의 절반을 만들었습니다. 떼어내고 수집·전송만 남기니 안정됐고, AI는 나중에 선택 기능으로 다시 붙였습니다.

실패해도 멈추지 않게

부가 기능이 실패해도 핵심 결과물(아침 뉴스)은 반드시 나가도록 설계합니다.

설정과 코드를 분리

키워드는 keywords.yml에. 마케터가 코드를 건드리지 않고 운영합니다.

사람의 일은 판단과 증거

"이 기사는 필요 없다", "이 시간에 또 왔다"를 캡처로 보여주는 것. 원인 추적과 수정은 AI가 합니다.
